# 余额管理增量同步：新建客户自动建档与刷新补建

## 背景

余额管理页默认只显示有 `customer_balances` 记录的客户。此前已通过一次性回填脚本为存量客户补建了余额记录，但缺乏持续保障机制：

1. 新建客户创建时虽已创建余额记录，但代码未使用防御性检查
2. 余额页刷新时不会自动检测并补建新增客户的余额记录

## 目标

确保余额管理页与客户管理页的客户数据始终一致，无需人工干预。

## 功能需求

### FR-1：新建客户按需创建余额记录（防御性加固）

- `create_customer` 创建余额记录时，改用 `get_or_create_balance` 模式防御性检查
- 不改变现有行为（新客户仍然创建余额记录）
- 防止恢复已删客户等边缘场景下重复创建或冲突

### FR-2：余额页刷新时惰性补建缺失余额记录

- `get_balances` 查询时自动检测并补建无余额记录的活跃客户
- 只补建完全缺失的记录（`CustomerBalance` 中不存在的 `customer_id`）
- 不覆盖已有余额记录（幂等）
- 不影响查询性能

## 约束条件

- 不覆盖历史数据（`UNIQUE` 约束 + 幂等补建）
- 补建范围：所有活跃客户（`deleted_at IS NULL`），不限行业/账号类型
- 零前端改动

## 验收标准

| AC | 描述 | 验证方式 |
|---|---|---|
| AC-1 | 新建客户后立即有余额记录（余额 0） | 创建客户 → 余额页搜索可见 |
| AC-2 | 余额页刷新自动补建缺失余额记录 | 直接插入客户 → 调用 get_balances → 自动补建 |
| AC-3 | 已有余额记录不受影响 | 已有余额的客户刷新后余额不变 |
| AC-4 | 幂等性：多次补建不重复创建 | 连续调用 get_balances 多次，余额表行数不变 |
| AC-5 | 所有测试通过 | `pytest tests/unit -q` 通过 |

## 非功能性需求

- 改动量：后端约 10-15 行
- 零前端改动
- 零数据库迁移
