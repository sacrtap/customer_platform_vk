# 预测消费：单价配置可视化与预测参数控制

## Goal

在预测消费页面中增加单价配置的可视化编辑功能，让用户可以直接修改单价矩阵后重新预测；同时支持预测范围控制（更新历史/仅后续、月份数选择）。

## In Scope

### 1. 单价配置可视化编辑
- 页面显示当前 L/N/X 三档单价（元/套）
- 用户可编辑单价值，点击"重新预测"后应用新价格
- 单价存储：新建 `forecast_unit_prices` 表或复用配置接口（避免 hardcode 在 config.py）
- 后端 API：`GET/PUT /api/v1/analytics/consumption/price-config`

### 2. 预测范围控制
- 预测参数面板增加两个选项：
  - **应用范围**：单选——"更新历史及后续月份" / "仅后续月份有效"
  - **预测月份数**：输入框或下拉选择（3/6/12/自定义），或选择具体截止月份
- 后端接口 `GET /analytics/consumption/forecast` 增加参数：
  - `apply_to`: `all`（默认，更新历史+后续） / `future_only`（仅后续月份）
  - `forecast_months`: 预测月份数（默认 12，最大值 24）
  - `forecast_until`: 具体截止月份（如 `2026-12`，与 forecast_months 互斥）

### 3. 预测算法适配
- 当 `apply_to=future_only` 时，预测明细只返回 >= 当前月份的数据
- 当 `apply_to=all` 时，按现有逻辑返回全年
- 趋势图同理适配

## Out of Scope

- 单价历史版本追踪（后续迭代）
- 批量修改单价（后续迭代）
- 单价导入/导出
- 权限细分（使用现有 `analytics:forecast` 权限）

## Acceptance Criteria

- [ ] AC1: 页面显示 L/N/X 三档当前单价，值可编辑
- [ ] AC2: 修改单价后点击"重新预测"，预测结果立即按新价格更新
- [ ] AC3: 单价修改后持久化，刷新页面后仍保留
- [ ] AC4: "仅后续月份"模式下，历史月份预测值不变
- [ ] AC5: "更新历史"模式下，全年预测均按新价格重新计算
- [ ] AC6: 预测月份数选择正常生效（3/6/12/自定义）
- [ ] AC7: 截止月份选择与月份数选择互斥
- [ ] AC8: 趋势图同步适配预测范围

## Key Decisions

| # | Decision | Value | Rationale |
|---|----------|-------|-----------|
| 1 | 单价存储 | 新建 DB 表 `forecast_unit_prices` | 可持久化、可 API 修改，优于 config.py hardcode |
| 2 | 默认行为 | `apply_to=all, forecast_months=12` | 向后兼容，现有页面行为不变 |
| 3 | 前端交互 | 内联编辑 + 确认按钮，不弹窗 | 简化操作路径，单价变更不频繁 |

## Risks

- 单价修改后，旧预测准确度记录（audit_logs）不会自动更新——这是预期行为，准确度记录的是当时预测值
- 如果用户频繁修改单价，预测结果跳跃大——建议在页面加提示"修改单价将影响后续预测"
