# CRM 充值管理 — 需求

## 背景

系统管理下新增「CRM 充值管理」。CRM（https://lxcrm.weiwenjia.com，官方开放 API v2）中行业分类为「房产经纪 / 新房开发」且审批通过的回款，需要人工核对后充值到指定中台客户；客户编辑页需支持 CRM 客户搜索、模糊推荐与手动绑定。

完整调研与实施设计见 `docs/specs/2026-11-11-crm-recharge-management-plan.md`（以下简称 PLAN），本文件只定义需求与验收。

## 核心数据流（固定，不得改变）

定时任务 → 经 CRM 接口完整读取当月符合行业与审批条件的回款 → 幂等录入 CRM 充值管理回款列表（无论是否已绑定中台客户）→ 人工逐笔核对 → 未绑定时到客户管理绑定 → 回到回款列表刷新 → 填写实充/赠送并「导入充值」→ 原子增加指定客户余额并生成充值记录。

- 同步本身**不创建**充值记录、**不改变**余额。
- 取消确认、导入失败、绑定操作均不改变余额。
- 本模块**不向 CRM 写入/修改/审批**任何数据，只读。

## 已确认产品决策

1. 严格一对一绑定：一笔回款只能生成一条充值记录，只入其 CRM 客户绑定的中台客户。
2. 实充默认 = CRM 回款金额，提交时必须等于源回款金额；赠送默认 0，可额外填写非负金额，不占用回款金额。例：回款 1000，实充 1000 + 赠送 200 → 余额 +1200。
3. CRM 导入禁止负数，实充与赠送不能同时为 0；现有手动/Excel 扣减行为不变。
4. 业务日期：最近充值、本月充值、充值趋势、结算明细按**实际回款日期**（`recharge_date`）；`created_at` 保持原值（导入时刻）；历史记录迁移时 `recharge_date = created_at::date`。
5. 每天 22:00 自动同步当月；另提供按月份手动同步（任意历史月，不可未来月）补取。
6. CRM 导入禁止包年客户；不改变现有手动/Excel 充值的客户类型规则。
7. 同源回款重复导入幂等：同目标客户 + 同实充/赠送返回原充值记录；任一金额或目标不同 → 409。
8. 不增加历史关联/标记已处理/自动金额匹配。页面确认框必须提示「无法识别上线前手工记过的账」。

## 验收标准

| 检查 | 输入/情境 | 可观测结果 |
|---|---|---|
| 行业与审批 | 房产经纪根/新业绩/老业绩、新房开发；公共安全、applying | 前四者 approved 当月可导入，另两者不可；按斜杠路径解析，不按客户所属行业 |
| 全分页 | mocked 103 客户、101 合同，第二页含当月 approved 回款 | 该回款进入镜像；中途业务 code=500 → run=failed，不报告「本月无回款」 |
| 月界 | 11-01 / 11-30 / 12-01 三笔；10 月回款 11 月审批 | 11 月同步只取前两笔；10 月只能手动同步 10 月补取 |
| 绑定并发 | 两客户同时绑定同一 CRM 客户；越权 customer_id | 仅一方成功另一方 409；越权 403 且不泄露他人客户名 |
| 候选排序 | 同名/包含/轻微错字/无关名；空白查询 | 确定顺序、阈值、top10；打开编辑不自动绑定；切换客户不残留 |
| 原子双金额 | 余额 real=1000 bonus=50；回款 200，实充 200 赠送 40，回款日 10-31 在 11 月导入 | real=1200、bonus=90、total=1290；一条充值记录 real=200 bonus=40；recharge_date=10-31；created_at=导入时刻；审计与源关联同事务 |
| 重试与并发 | 同回款并发两次；不同回款并发同客户；手动与 CRM 并发 | 同源只加一次返回同 ID；异源不丢账；余额无记录时也不出现两行 |
| 幂等赠送保护 | 200/40 成功后重试 200/40；再请求 200/60 | 同值返回原 ID；改赠送 409；并发仅一组成功 |
| 同步与绑定分离 | 两条符合回款一条未绑定 | 同步/绑定/取消均不改余额；绑定后无需重同步即可导入 |
| 入账门槛 | 160+40=200、负数、双 0、NaN、超精度、伪造日期、未绑定/包年/停用/删除、上游撤审/变更 | 160+40 拒绝（实充≠源金额）；其余拒绝且无半成功 |
| 业务日期切换 | 10-31 实充 200+赠送 40 在 11 月导入；11-01 另 300+60 | 最近日期=11-01；11 月统计只含 300+60，10 月含 200+40 |
| CST 边界 | period_start=2026-10-31T16:00:00Z、period_end=2026-11-30T15:59:59Z | 窗口 11-01~11-30，含 11-01/11-30，不含 10-31 |
| 已导入源变更 | 导入 200 后源变 300/撤审 | 原充值不变，source_changed 展示；重试不补差、不再加、不自动退款 |
| 调度与长任务 | 注入 CST 2026-11-30 22:00 触发；运行超 30 分钟 heartbeat 持续；双 worker | month=2026-11-01 且 running；仅一个 run 获得执行权；>2 分钟无 heartbeat 可恢复 failed |
| 权限隔离 | 无模块权限/view only/import 无 billing:recharge/无 view_all | 403；view 无写；import 需充值权限；业务用户看不到未绑定/他人回款、金额与总数 |
| 迁移回填 | 迁移前 created_at='2026-10-31 23:59:00' | recharge_date=2026-10-31，created_at 不变，约束生效 |
| 清理保护 | 存在 CRM 导入记录时清空余额数据 | 409 拒绝整次清空，不丢入账凭据 |

## 非目标

- 批量/自动充值、自动冲正、历史账自动匹配、向 CRM 回写、通用集成平台、任务队列/SDK/模糊匹配库、独立 CRM 数据备份。
