# 客户360预览信息增强与冗余按钮下线（PRD）

## 背景

客户列表行的「详情」入口打开的是「客户 360 预览」抽屉（`frontend/src/views/customers/components/PreviewDrawer.vue`）。
抽屉目前只展示客户名称/行业/等级、4 个 KPI（余额、30天消耗、健康度、预计耗尽）和两个无实现的按钮
（「生成结算单」「提醒充值」）。运营需要在抽屉内快速判断客户状态，但大量基础字段（客户编号、经理、
结算配置、合作状态、ERP、接入/首付日期等）必须跳转详情页才能看到。此外「最近操作」时间轴依赖
`consumption_history`，该字段后端任何接口都未返回，区块恒为空。

## 需求

| # | 需求 |
|---|---|
| 1 | 抽屉在现有「客户信息 + KPI 四宫格」基础上新增**基础信息**区块，展示：客户编号、账号类型、重点客户、房产客户、运营经理、销售经理、结算方式、结算周期、结算账户、合作状态、是否结算、是否对账、是否停用、邮箱、所属 ERP、接入时间、首次回款时间、备注、创建时间 |
| 2 | 打开抽屉时调用客户详情接口（`GET /api/v1/customers/:id`）补全列表未返回字段（ERP、合作状态、接入/首付日期、停用、备注、结算账户名称）；请求失败时静默回退到列表行数据，不阻塞抽屉展示 |
| 3 | 字典字段显示中文：结算方式（预付费/后付费）、结算周期（日结/周结/月结/季结/年结）、合作状态（取字典，回退内置映射）、ERP 直接展示字典名称 |
| 4 | 删除抽屉内「生成结算单」「提醒充值」两个按钮（无点击实现），保留「查看详情」 |
| 5 | 删除恒为空的「最近操作」时间轴区块，空间让位给基础信息 |

## 约束

- 纯前端改动，不改后端接口与数据模型。
- 不改客户详情页、列表页其它区域；不改首页「快捷操作」里的同名按钮。
- 沿用抽屉现有视觉体系（`--line` / `--muted` / `--ink` 等 CSS 变量、圆角卡片风格）。

## 验收标准

1. 打开任意客户的 360 预览，可见上述全部基础信息字段；空值统一显示 `-`。
2. 抽屉内不再出现「生成结算单」「提醒充值」按钮，且不出现「最近操作」区块。
3. 详情接口失败（断网/403）时抽屉仍展示列表行已有的客户信息与 KPI，无错误弹窗。
4. 运营经理/销售经理显示姓名；字典缺失时显示 `#id` 兜底，不显示空白。
5. `npm run type-check`、`npm run lint` 通过；相关单测通过。

## 非目标

- 不新增后端字段或修改列表序列化。
- 不在抽屉内提供编辑/充值/结算等写操作入口。
