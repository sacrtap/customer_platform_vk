# 客户运营中台硬规则

- **数据库事务**：所有修改操作必须在 `async with db_session.begin():` 块内执行
- **权限校验**：所有 API 端点必须添加 `@auth_required` 装饰器
- **测试覆盖率**：CI 要求测试覆盖率 ≥50%（全量口径：单元+集成 coverage 合并判定，`--cov-fail-under=50`，见 `.github/workflows/pr-checks.yml`）
- **Python 版本**：必须使用 Python 3.12.x，不支持 3.13+
- **并发安全**：余额扣款使用行级锁（`FOR UPDATE`）防止冲突
- **文件修改前必须先读取**：避免基于过时快照编辑

## 经验沉淀（学习捕获）

- **可复用经验必须落盘**：任务中发现的可复用经验（调试根因、非显而易见的修复、项目约定、工作流诀窍），必须经 `.agents/skills/trellis-update-spec/` 沉淀到 `.trellis/spec/`，或经 `learn` 记录到长期记忆；禁止只留在会话里。
- **沉淀内容需可追踪**：每次沉淀记录基线问题与预期改进，供后续同类任务对照验证效果（见 `.omp/rules/conventions.md`「基线 → 预期改进」约定）。

## 可靠交付（验收证据）

- **交付任务必须写明验收边界**：涉及合并/交付的任务（功能、修复、迁移、部署），结束前必须写明「验收边界 + 最终验证结果」——目标是什么、改动涉及哪些文件、跑了哪些验证、结论通过与否。可写在 PR 描述、任务笔记或 `.trellis/tasks/` 中，禁止只停留在会话里。
- **验收结论可复核**：验收结论应与可复核证据关联（CI 运行、测试输出、健康检查结果），使他人能在仓库内验证，而非依赖会话记忆。

## 个人偏好
